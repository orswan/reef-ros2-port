## Changes

- **Finding 1.** `XYZEstimator` snapshots the plus states when the estimate
  is produced, before the takeoff check (`publishedZ()`, `publishedXY()`);
  `toEstimateMsg`/`toDebugMsg` build the plus fields from them. The minus
  fields were already saved before propagation and are unchanged.
- **Why the parity checks missed it, and the new check.** Harness and port
  both recorded the state after the callback. The harness now also records
  the messages the original actually published (adaptation A6,
  [baseline/README.md](../../baseline/README.md): a shim hook in
  `ros::Publisher::publish`; the pinned sources are unmodified), and the
  event driver writes the port's messages in the same format.
  `check_port.py` compares them on all 50 streams (group `published`).
  Unit test `EstimateIsTakenBeforeTheTakeoffCheck` covers the takeoff step.
- **C1 default.** Parity runs (`check_port.py`, faults F-parity) pin
  C1 off so they still compare against master. New group `c1`: the
  independent step-wise model (`independent.py`, extended with C1 and with
  `enable_xy`/`enable_z` gating) must equal the original with C1 off and the
  port's default output with C1 on.
- **Faults.** F1 and F11 are judged on the default configuration; the legacy
  C1-off runs remain as asserted characterizations of D1 (re-fusion, and the
  F11 lock-out). F11's 0.10 m/s limit is unchanged.
- **Docs.** ACCEPTANCE (explained amendment: C1 default, F1/F11, published
  messages), AGENTS, BASELINE_DECISION (§1, §7), INTERFACES (§1, §3, §3.7,
  §3.9), STATUS.
