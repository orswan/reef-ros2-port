## Claim

The estimator's dependencies are ported with nothing invented:
- `reef_msgs`: the 7 messages and 5 helper functions that master `e4179f48`
  uses, with upstream history preserved. The helpers are bit-identical to the
  pinned originals.
- `RCRaw`: the unmodified upstream ROS 2 `rosflight_msgs` (v2.0.1), whose
  layout matches the ROS 1 message.
- Parameters: every legacy parameter is declared, typed and validated;
  invalid input stops the node instead of producing zeros or garbage.
- The node's ROS 2 interface is defined (INTERFACES.md §3). The node itself
  is P04.

## Decisions a reviewer may want to question

1. **Vendoring instead of fetching** `rosflight_msgs`: offline and small,
   guarded by the tree-ID check. The alternative is a pinned fetch at build
   time.
2. **Invalid parameters are fatal** (D10 not preserved). This cannot change
   valid configurations; all 16 P02 fixture parameter sets pass the new
   validation.
3. **Integers accepted for double parameters**, as roscpp did, so the gates
   written as `20` stay valid. Bool, integer, and string parameters need
   their exact type (roscpp silently used the default instead).
4. **Empty `frame_id`** on outputs, because one message mixes two frames;
   the frames are defined per field in INTERFACES.md §3.3.
5. **`is_flying_reef` only on transitions**, as in ROS 1, so nothing is
   published before the first takeoff.
6. **No reorder buffer** in the live node (INTERFACES.md §3.8).

## Dev-container failure and fix (2026-09-30)

USER ran `reef_check.sh interfaces` in `reef_ros2_dev` at `7963c84`: FAIL in
the colcon step, `No rule to make target '/opt/ros/jazzy/lib/libfastcdr.so.2.2.7'`.
[V] `build/reef_msgs` on the shared bind mount had been configured in the
original container, whose fastcdr is 2.2.7; the dev image's differs, so the
generated makefiles named a library that does not exist there. The code was
not at fault; the check reused another environment's build tree.
Fix: `scripts/check_colcon.py` builds, installs, and logs in
`build/colcon_check/<env>/`, where `<env>` hashes `dpkg-query -W` output, so
each container has its own tree and never reads `build/<pkg>`. The stale
outputs of `reef_msgs`, `reef_estimator`, and `rosflight_msgs` in the shared
tree were removed; the README warns about manual builds in both containers.
Rerun in the original container with a deliberately stale shared tree: PASS
5/5, 89 test cases. A faithful reproduction needs the dev image, so the
confirming run there is H5.
