## Claim

The vertical filter of reef_estimator master `e4179f48` is ported to ROS 2
without algorithmic change (C1–C5 deferred to R1) and reproduces the
original **bit for bit** on every compared value of 40 event streams. The
ROS 2 node publishes exactly the core's state. Beside the stock-controlled
simulated X3, on **idealized inputs** (truth attitude, idealized range) and
with an **IMU vibration assumption**, it estimates altitude to 6.8 mm RMS and
vertical velocity to 0.037 m/s RMS. REEF is not in the control loop. The
horizontal filter is NOT IMPLEMENTED (P05).

## Defect found and fixed during P04

The backward-jump reset first ran inside rclcpp's jump callback. The test
showed that Jazzy's time source calls it from its own thread, so the
estimator state could be changed concurrently with the executor. The handler
now only sets an atomic flag; the next message callback applies the reset
on the executor thread (`4b26e6b`).

## Decisions a reviewer may want to question

1. **IMU vibration assumption** in the simulation runs (above). Alternatives:
   a measured vibration level, or treating the takeoff detector as a
   correction candidate for R1.
2. **NaN** in the horizontal output fields until P05, instead of not
   publishing them or publishing zeros.
3. **No reorder buffer**; live results depend on delivery order like ROS 1.
   Live and offline estimates of the same run differ at the start
   (initialization offset), not in the metrics.
4. **History rewrite** to drop the third-party PDF from the imported
   reef_estimator history.
5. Output QoS reliable + transient local for every formerly latched topic.
